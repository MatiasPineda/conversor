# How conversor works

## Layout

```
cmd/conversor/        the CLI: hands os.Args to internal/cli
cmd/conversor-app/    the desktop app: single instance, Fyne app (needs cgo)
internal/core/        formats, options, presets, routing, running and publishing jobs, batches
internal/engines/     the engines, tool discovery, process control, packs
internal/codec/       image codecs Go lacks: BMP, ICO, TGA, PNM, QOI, OpenEXR, GIF quantizer
internal/cli/         the cobra command tree, reporter, SKILL.md
internal/app/         the app's state without windows: settings, history, job queue,
                      automations, requests, single-instance socket, Quick convert rules
internal/gui/         the Fyne windows and tray (cgo-free; tested headless)
internal/integrate/   right-click menus per OS (build-tagged)
internal/notify/      desktop notifications per OS
internal/i18n/        Spanish and English messages, system language detection
```

## Routing

Each engine declares the direct steps it can do (`png → jpeg`). `core.Registry` keeps the highest-priority engine for every step and finds routes with a breadth-first search capped at three hops. Ties break by engine priority, then by preferring lossless in-between formats, then alphabetically, so the same request always takes the same route. A step that turns a still into video or audio is only allowed as the first hop.

`Registry.Run` runs each hop on every file the previous hop produced. A PDF fans out to pages, and each page keeps its number through later hops. Work happens in a hidden staging folder inside the destination. Publishing reserves every final name with an exclusive create, then renames into place, so a job never replaces a file, and two jobs that pick the same name both survive. Cancellation is a `context.Context`; tools are killed with their whole process group (`taskkill /T` on Windows).

## Engines

| Engine | What runs | Notes |
|---|---|---|
| `image` | Go: stdlib, x/image, `internal/codec`, gen2brain/webp, avif, heic | WebP/AVIF/HEIC use libwebp, libavif and a HEVC decoder compiled to WebAssembly, so nothing needs installing. A system libwebp/libavif is used when present. |
| `pdfium` | PDFium compiled to WebAssembly (klippa-app/go-pdfium) | Embedded. Compiled code is cached under the user cache dir, so later starts are fast. |
| `svg` | resvg or rsvg-convert, else srwiley/oksvg | The built-in renderer has no text support. |
| `ffmpeg` | the `ffmpeg`/`ffprobe` binaries | Progress from `-progress pipe:1`; inputs restricted to self-contained containers, so playlists can't pull in other files. |
| `libreoffice` | `soffice --headless` | Each job gets a private profile, so several can run at once. |
| `libheif` / `imageio` | `heif-enc`, or `sips` on macOS | Only for HEIC output. |

## Design choices

- **No accounts, cloud, telemetry or auto-update.** Nothing leaves the machine except `pack install`, which asks winget or Homebrew for a tool.
- **WebP output**: lossy at quality 90 from lossy sources (JPEG, HEIC, AVIF), lossless from lossless ones (PNG, BMP, PDF pages, …). `--quality` always makes it lossy. Always-lossless WebP would come out twice the size of the source JPEG.
- **AVIF input** works everywhere, with no system library.
- **AVIF output** goes through FFmpeg's libaom when it's installed and the image is opaque: about 20× faster and a tenth of the memory of the WebAssembly encoder. Otherwise the embedded encoder runs, one at a time.
- **OpenEXR**: NONE, RLE, ZIPS and ZIP are read natively. PIZ, PXR24, B44 and DWA files are decoded by FFmpeg when it's installed.
- **Packs**: `pack install` uses winget or Homebrew for LibreOffice, FFmpeg and libheif, since a single binary can't bundle them.
- **Right-click menus** call the desktop app when it's installed and the CLI with `--notify` otherwise.
- **Desktop app**: Fyne. History is a JSON-lines file. macOS gets Quick Actions rather than a Finder Sync extension.
- **Resizing** uses Catmull-Rom.

## Testing

`go test ./...` runs everything. Tests that need FFmpeg skip without it. `internal/engines/testdata` holds three small MIT-licensed HEIC/AVIF fixtures; every other fixture, including the PDFs, is generated by the tests.
